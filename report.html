Project Overview

Visit Freetown Tourism Website

A comprehensive tourism website designed to promote Sierra Leone's capital city, Freetown, as a premier travel destination in West Africa.

Key Features
Destination Discovery

Interactive destination cards with detailed information about beaches, landmarks, and cultural sites

Itinerary Planning

Day-by-day trip planning with activity scheduling and date management

Wishlist Management

Save favorite destinations for future reference with localStorage persistence

Accommodation Guide

Comprehensive hotel listings with interactive maps and filtering options

Weather Integration

Real-time weather data using OpenWeatherMap API

Currency Converter

Live exchange rates for travel budget planning

Itinerary Planning System

Description

The itinerary planning system allows users to create, manage, and organize their travel plans day by day. This feature replaces the traditional "task allocation system" with a tourism-focused trip planning tool.

Core Functionality
  • Multiple Itineraries: Users can create and manage multiple trip plans simultaneously
  • Day-by-Day Planning: Each itinerary can have multiple days with specific dates
  • Activity Management: Add, view, and remove activities for each day
  • Data Persistence: All itineraries are saved to localStorage for cross-session access
  • CRUD Operations: Full Create, Read, Update, Delete functionality for itineraries and activities
Technical Implementation
File: js/itinerary.js

Key Functions:

  • createNewItinerary() - Creates new trip plans with unique IDs
  • switchItinerary(id) - Switches between different itineraries
  • addDay() - Adds new days to the current itinerary
  • addActivity(dayIndex) - Adds activities to specific days
  • deleteItinerary(id) - Removes itineraries with confirmation
  • saveAllItineraries() - Persists data to localStorage
Data Structure
{
  id: "ITN-abc123",
  name: "My Sierra Leone Trip",
  days: [
    {
      day: 1,
      date: "2026-07-01",
      activities: [
        "Visit River No. 2 Beach at 10:00 AM",
        "Lunch at local restaurant",
        "Explore Cotton Tree"
      ]
    }
  ],
  createdAt: "2026-06-17T12:00:00.000Z"
}
User Interface

The itinerary interface is located at analytics.html and features:

  • Input field for naming itineraries
  • List view of all created itineraries with day counts
  • Action buttons for each itinerary (Add Day, View, Delete)
  • Expandable day cards with date pickers and activity lists
  • Visual highlighting of the currently active itinerary

Wishlist Feature Documentation

Description

The wishlist feature allows users to save their favorite destinations for future reference. This acts as the "latest activity section" equivalent, tracking user interactions with destinations.

Implementation Details
File: js/wishlist.js

Core Functions:

  • toggleWishlist(destinationId) - Adds/removes destinations from wishlist
  • isInWishlist(destinationId) - Checks if destination is saved
  • getWishlistItems() - Retrieves all saved destinations
  • updateWishlistUI() - Updates heart icon states across the site
Features
  • Persistent Storage: Uses localStorage to maintain wishlist across sessions
  • Visual Feedback: Heart icons change color when destinations are saved
  • Cross-Page Sync: Wishlist state is consistent across all pages
  • Toast Notifications: User feedback when adding/removing items
Integration Points
  • Destination cards on homepage and destinations page
  • Destination detail modals
  • Accommodation listings

Destinations Page Documentation

Description

The destinations page serves as the "personal page" equivalent, showcasing Sierra Leone's top tourist attractions with detailed information, reviews, and interactive features.

Technical Implementation
File: js/destinations.js

Key Components:

  • destinations array - Contains all destination data
  • renderDestinations() - Dynamically generates destination cards

  • filterDestinations(category) - Filters by destination type

  name: "River No. 2 Beach",

  • Responsive Design: Grid layout adapts to all screen sizes
  • Image Optimization: Lazy loading and proper sizing
User Interactions
  • Click destination cards to view details
  • Add destinations to wishlist with heart icon
  • Submit reviews and ratings
  • View location on interactive map
  • Share destinations on social media

Reflections & Challenges

Development Journey

Major Challenges Faced
1. Code Organization and Refactoring

Challenge: Initial code had significant duplication across multiple JavaScript files, making maintenance difficult.

Solution: Created a centralized utils.js file with shared utility functions:

  • generateId() - Unique ID generation for all features
  • getStorage() / setStorage() - Centralized localStorage management
  • sanitizeInput() - Input validation and XSS prevention
  • showToast() - Consistent user feedback across the site

Impact: Reduced code duplication by ~40% and improved maintainability significantly.

2. Image Path Management

Challenge: Broken image paths after restructuring the images folder, affecting hero sections, destinations, and accommodations.

Solution: Implemented a systematic approach:

  • Reorganized images into logical folders: accommodations/, destinations/, navigation/, backgrounds/
  • Renamed all images with consistent naming conventions (lowercase, hyphens)
  • Updated all references in HTML, CSS, and JavaScript files
  • Moved unused images to dedicated unused/ folder

Impact: Improved project organization and eliminated all broken image references.

3. Itinerary State Management

Challenge: Itinerary buttons (View, Delete, Add Day) were not working due to ID type mismatches between strings and numbers.

Solution: Implemented consistent string comparison:

  • Added String() conversion in all ID comparisons
  • Fixed onclick handlers to pass IDs as strings: '${itinerary.id}'
  • Added setTimeout() for sequential operations to prevent race conditions
  • Improved error handling with better null checks

Impact: All CRUD operations now work reliably across different itineraries.

4. LocalStorage Data Persistence

Challenge: Inconsistent data handling across features leading to data loss and errors.

Solution: Created standardized storage utilities with error handling:

  • Centralized JSON parsing/stringifying with try-catch blocks
  • Default value support for missing data
  • Consistent data structure validation

Impact: Zero data loss incidents and improved user experience.

5. Responsive Design Consistency

Challenge: Ensuring consistent user experience across mobile, tablet, and desktop devices.

Solution: Leveraged Bootstrap 5's grid system and utility classes:

  • Mobile-first approach with progressive enhancement
  • Responsive navigation with hamburger menu
  • Flexible card layouts that adapt to screen size
  • Touch-friendly interactive elements

Impact: Seamless experience across all device types.

Key Learnings
  • Planning is Crucial: Proper project structure from the start saves significant refactoring time
  • DRY Principle: Don't Repeat Yourself - shared utilities improve code quality
  • Type Safety: JavaScript's loose typing requires careful handling of data types
  • User Feedback: Toast notifications and visual feedback greatly improve UX
  • Version Control: Git commits helped track changes and revert when needed
  • Testing: Regular browser testing prevented many issues from reaching production
Future Improvements
  • Implement backend API for data persistence beyond localStorage
  • Add user authentication for personalized experiences
  • Integrate booking system for accommodations
  • Add more interactive maps with custom markers
  • Implement Progressive Web App (PWA) features
  • Add multi-language support for international visitors
